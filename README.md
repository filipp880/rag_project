# Multi-Step RAG Agent

## О проекте

Multi-Step RAG Agent - локальный многодокументный RAG-ассистент с гибридным поиском,
кросс-энкодерным реранкингом и агентом, вызывающим инструменты. Система отвечает на
вопросы по загруженным документам, указывает источники ответов и умеет отвечать без использования базы знаний, используя инструменты: (погода, вычисления). Всё работает локально:
без внешних API и платных сервисов.

### Что делает система

Пользователь задаёт вопрос в командной строке (**agent.py**). LLM (llama3.2 через Ollama) сама
решает, как отвечать: напрямую, поиском в базе знаний или вызовом инструмента.
Если нужен поиск, запускается retrieval, найденные чанки передаются модели
как контекст, и агент формулирует ответ. Система обязательно выводит строку
«Источники: ...» - для того, чтобы было видно, из какого файла пришёл ответ. Диалог сохраняется в историю
и переживает перезапуск программы.

### Как работает

**1. `ingest.py`**
- Читает все `.txt`-файлы из `data/`.
- Разбивает текст на чанки фиксированного размера (500 символов) с перекрытием
  (150 символов): перекрытие сохраняет связность текста на границах чанков.
- Строит эмбеддинги чанков моделью `paraphrase-multilingual-MiniLM-L12-v2`.
- Сохраняет чанки, эмбеддинги и метаданные (`source` - имя файла-источника)
  в ChromaDB с метрикой cosine.

**2. `retrieval.py`**
- Семантический поиск: ближайшие чанки по косинусному сходству эмбеддингов в ChromaDB.
- Лексический поиск: BM25 по лемматизированным токенам (pymorphy3) - ловит точные
  термины и имена, которые пропускает семантика.
- Объединение рангов: Reciprocal Rank Fusion - `score(doc) = Σ 1/(60 + rank)` по рангам
  из обоих списков; масштабно-независимое объединение разнородных скорингов.
- Опциональный реранкинг: кросс-энкодер `BAAI/bge-reranker-v2-m3` переоценивает
  топ-20 кандидатов и возвращает точный топ-3.

**3. `agent.py`**
- Multi-step цикл: модель может вызывать инструменты несколько раз подряд, пока не
  ответит без вызовов; защита от зацикливания - `max_iterations`.
- Инструменты: `search_article` (гибридный поиск по базе знаний), `get_weather`,
  `calculate`.
- Цитирование источников: retrieval возвращает чанки с полем `source` в метаданных,
  источники выводятся кодом, а не полагаются на надёжность модели.

**4. `main.py`**
- Интерактивный диалог в консоли; команды `/history`, `/clear`, `/quit`.
- История диалогов хранится в `history.json` между сессиями.

**5. `retrieval.py`**
- Размеченный набор вопросов с ожидаемым источником ответа.
- Recall@3 - доля вопросов, где нужный документ доставлен в топ-3 (то, что реально
  уходит в контекст LLM); MRR@3 - качество ранжирования внутри топ-3.
- A/B-режимы: семантика vs гибрид, с реранкером и без, с лемматизацией и без.

### Используемые модели

| Компонент | Решение |
| :--- | :--- |
| Эмбеддинги | `paraphrase-multilingual-MiniLM-L12-v2` |
| Лексический поиск | BM25 (`rank_bm25`) + лемматизация `pymorphy3` |
| Реранкинг | `BAAI/bge-reranker-v2-m3` |
| Генерация | `llama3.2` (Ollama, локально) |
| Векторная БД | `ChromaDB` (cosine) |

## Структура проекта
* `data/` - директория для текстовых документов и баз знаний.
* `ingest.py` - скрипт загрузки, чанкинга с перекрытием и индексации в ChromaDB.
* `agent.py` - логика работы агента, фильтрация метаданных и цикл вызова инструментов.
* `retrieval.py` - модуль гибридного и семантического поиска (BM25 + RRF) и оценки его качества.
* `main.py` - точка входа для запуска диалога с агентом.
* `requirements.txt` - список зависимостей проекта.

## Оценка качества поиска

Оценка качества поиска проводилась на тестовом наборе запросов с фиксированной глубиной выдачи $K=3$:

| Метод поиска | Recall@3 | MRR@3
| :--- | :--- | :--- |
| **Семантический поиск** | 0.92 | 0.821
| **Гибридный поиск (без реранкера, без лемм)** | 1.00 | 0.859
| **Гибридный поиск + BGE-M3(без лемм))** | 0.92 | 0.923
| **Гибридный поиск (без реранкера + лемматизация)** | 1.00 | 0.795
| **Гибридный поиск + BGE-M3 + лемматизация)** | **1.00** | **1.000**

## Результаты реранкинга

>Мультиязычный реранкер (BGE-M3) улучшил MRR@3 с 0.859 до 0.923 (+7.5%), но снизил Recall@3 с 1.00 до 0.92.  
**Вероятная причина:** агрессивное переупорядочивание на запросах с неточными формулировками. Для работы в реальных условиях рекомендуется A/B-тестирование обоих реранкеров на реальных пользовательских запросах.

## Результаты лемматизации

>Лемматизация ухудшила качество ранжирования без реранкера (MRR 0.859 -> 0.795), скорее всего из-за того, что разные чанки стали выглядеть похоже после приведения к леммам. Реранкер компенсировал это ухудшение: пара (query, doc) видна ему целиком и результат не зависит от токенизации.  
**Итог:** лемматизация + реранкер - это лучший результат, но без реранкера лемматизацию лучше не использовать.

## Известные ограничения (Known Limitations)
**Планирование 3B-моделей (llama3.2):** Небольшие локальные модели могут вызывать итоговые инструменты с некорректными/выдуманными параметрами вместо последовательного выполнения всей цепочки вызовов (например, прямого вызова `calculate` вместо последовательности `get_weather` ➔ `calculate`).
## Roadmap:

### Приоритетные

1. **Обработка ошибок в инструментах (graceful degradation)**: при ошибке вызова API агент должен предлагать fallback-варианты ("Не удалось получить погоду, но могу поискать в базе знаний").
2. **Конфигурация через YAML**: вынести параметры чанкинга, retrieval и моделей в отдельный файл.
3. **Unit-тесты (pytest)**: покрытие чистых функций (`chunk_with_overlap`, `rrf_fusion`, `tokenize_lemmas`).
4. **Структурированный логгинг**: замена `print()` на `logging` с уровнями и форматированием.
5. **Увеличение размера модели / Декомпозиция:** Использование более крупных моделей (от 8B параметров и выше) или явная декомпозиция сложных мультистеп-запросов перед передачей их агенту.

### Долгосрочные

5. **BGE-M3 sparse+dense**: замена пары BM25 + MiniLM на единый BGE-M3 с тремя режимами эмбеддингов.
6. **Docker-compose**: упаковка ChromaDB и приложения в контейнеры для воспроизводимого запуска.
7. **Tracing (Langfuse/Phoenix)**: визуализация цепочек вызовов агента и метрик по шагам.
8. **NDCG@K**: продвинутая метрика ранжирования с градацией релевантности.

## Быстрый запуск

Для работы агента требуется установленный и запущенный **Ollama** с загруженной моделью (например, `llama3.2`).
```bash
pip install -r requirements.txt
python ingest.py # построение базы знаний из /data
python main.py # диалог с агнтом
python retrieval.py # Recall@3 и MRR@3 оценка качества
